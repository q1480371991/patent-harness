## 〇、一句话结论

格式/模板/套话类问题（H2609029 出现 6+4 处）**已全部机械化**：模板句有了唯一副本 `boilerplate.py`，DOCX 有了 `verify_docx_skeleton.py` 的分节落位/标题格式/权要段行距/名称=给定名称/空段五类校验，
交付前跑三个脚本即可确定通过与否，**不再依赖 LLM 记不记得**。盘点结论：**无需新增格式 auditor**——剩下的格式类判断只有 3 处「两种合法写法并存」，不该机械判。

## 二、新增/改动的脚本（怎么跑、何时跑）

### 2.1 新增

| 脚本 | 用途 | 关键用法 |
|---|---|---|
| **`boilerplate.py`** | **模板句唯一副本**（13 句）：落笔前填空渲染 + 逐字校验 | `render --method-name X --system-name Y`（整句粘贴）；`check --md docs/全文稿.md --claims-md docs/权要稿.md` |
| **`docx_assets.py`** | 交付 DOCX 里用户手工资产（Visio/EMF）的查看/抠出/回注——**重建前备份用** | `list` / `extract <旧稿.docx> --out docs/_assets-备份/` / `restore <新稿.docx> --from …` |

### 2.3 交付前三个脚本（顺序固定）

```bash
python scripts/boilerplate.py check --md docs/全文稿.md --claims-md docs/权要稿.md          # 13 句模板句逐字
python scripts/verify_docx_injection.py <交付稿.docx> --md docs/全文稿.md                     # 注入机械项 + 模板句（DOCX 层）
python scripts/verify_docx_skeleton.py <交付稿.docx> --stage 全文 --invention-name "<给定名称>"  # 骨架/分节/标题/行距/空段/名称
```
