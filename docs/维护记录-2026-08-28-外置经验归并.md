#### 批 5 的两个实质发现

**① 阈值段少了「取值可调区间」这一维，而审核人三个示例全写了。**

`正式派单/阈值设定方式.md`（审核人给的原始材料）三个示例逐一印证：「该阈值可根据具体应用场景（如男性低沉语音或儿童尖锐语音）在 **±500Hz 范围内**进行调整」／「85% 是经验值，可在 **80% 至 95% 范围内**选择；对精度要求高的场景可选 95%，对实时性要求高的场景可选 80%」／「在多个候选阈值（0.05, 0.1, 0.15）下执行……选择使准确率最高的候选值」。

skill 里「取值范围」**只在公式五项里有**（G6-1 第④项），阈值段没有这一维。→ 已补为八槽的**第 9 槽**。

这条同时填掉了一个真空：末尾参数兜底句已定性为一般不写、`check_preset_params.py` 槽 5「工况变化时重新执行」降为 WARN 级之后，**「这个值可调」这层意思本来没有落点**（X2608107 定稿实测 3 个预设量缺槽 5、兜底句又被删，可调整语义在定稿里确实无处体现）。现在由第 9 槽承载。

⚠️ 与 X8「只给一种设定方式」的边界写进了条内：**X8 禁「多种确定方法」，第 9 槽要「一种方法下的取值区间」**，两条不冲突。

### 批 6 · 第五路 reviewer-sim（审核人视角复核）

审核人当日另发一份**自用审查提示词**（`正式派单/王工审查自用提示词.md`，五段，每段标题即他标的用途）。本批把它做成 skill 的**第五路**，与既有四路 auditor **互补而非替代**。

**判据比对结论**：②「逐条权要」六条判据本 skill 全有；**七个新判据集中在①③⑤**——行业真实创新方向、违背行业习惯、数值不合常理、计算算式错误、补写形态约束、公式字母变量前后含义重复、是否符合领域常规理论。

**七条的共同点，也是第五路的设计依据**：它们全都**拿领域知识校验**，而本 skill 所有规则都**拿稿件自身校验**。既有四路本质是**一致性检查器**（内部自洽、与权要同构、槽位填全），这七条是**领域知识检查器**。**一个内部完全自洽的方案可以整体不合常理** —— 这是第五路存在的理由。

| | 既有四路 auditor | 第五路 reviewer-sim |
|---|---|---|
| 判据来源 | `references/rules/`（我们的标准） | 审核人自用审查提示词（他的标准） |
| 检查性质 | 一致性检查 | 领域知识检查 |
| 输出 | PASS/FAIL + 评分 + 最短回修清单 | **疑点清单 + 依据**，无评分 |
| 权力 | 1 级 FAIL 阻断 DOCX | **无否决权**，不阻断 |
| 时点 | 机械脚本 PASS 后 | **四路/三路全部 PASS 之后** |
| 落盘 | `docs/审查报告-<稿次>.md`（过闸凭证，须清零） | `docs/审稿人视角复核-<稿次>.md`（疑点备忘，不必清零） |

**四条关键设计**：

1. **独立性靠工具白名单强制，不靠嘱咐** —— 契约明文禁止 Read `references/rules/`、`agents/`、`references/cases/`，且不传任何 `*_rules_path`。一旦它读了我们的规则，就又成了"用我们的标准审我们的稿"，正是五案连续"自审全 PASS 然后挨批注"的成因。`rules.md` 也加了这条反向读取纪律（本表其余各路都读规则，唯它不读）。
2. **提示词其二末段是豁免、不是要求** —— 上位概括的算法/模型会在说明书补充、权要中预设或获取的特征来源视为合规、判断分支会在说明书补充。不显式执行，本路在权要阶段会大量误报"预设阈值没说来源"，而那恰恰是审核人明确说不要挑的。
3. **「无需修改」项要单独列出** —— 审核人写的是「合理的修改，**不合理的不修改**」。故输出契约有专门一段：凡看过但认为不必改的，列出 + 一句理由。这是为了区分「没看」与「看过觉得没问题」（同根因四补一维的精神）。
4. **spec 侧要求先复述技术方案主链** —— 提示词其三第一句是「**先理解技术方案的结构和各部分内容**，然后分析…」，做成输出契约第 0 段（5–10 行复述输入→处理→输出）。**复述不出来本身就是 26.3 疑点**。

**前置与验收的分工**：判据①②（行业创新方向、行业习惯）**必须前置到写之前**（写完才发现方向错就白工），故同时落 `SKILL.md` step 2.5 第④项；第五路在交付前以同样判据复核一次，并**优先复用 `facts.md` 里 step 2.5 的检索结果、不重复检索**。这与「公式必要性判断时点＝写之前」同一思路。

**联网**：白名单含 Tavily（优先）与 WebSearch，仅用于判行业现状/领域常规理论/数值量级。⚠️ **禁止把交底书、权要、说明书原文贴进查询**，查询词只能是抽象后的公开技术术语（第三方端点会缓存与索引）。

**返修轮的调用口径**（由主 agent 按批注**实际性质**决定，不按条数、不询问用户）：①纯措辞/格式/编号迁移类小修 → 不调用；②批注触及方案层或技术实质 → 调用；③**本轮返修的改动质量本身不可信**（未遵守 skill、把内容改坏、同一处连续两轮改不对）→ **必须调用**，此时它审的是"改烂了没"。**定稿轮不强制**（定稿即不再改，该轮改动留全案复盘）。

**未采纳的一项**：审核人写「最好开两个 ai 交叉印证」。当前只跑一遍——成本翻倍而收益不确定；实测发现漏检再启用，且第二遍应**换模型**跑（重点在异质性不在数量）。

**同批处置的三个孤儿文件（已删）**：`references/rules/writing-brief-{claims,content,global}-trial.md`（247 行）。它们是上游作者「把撰写预读改成最小清单」实验的产物，实施路径 4 步（见 `docs/规则读取流程.md`「优化方向（已与用户对齐，未实施）」），**只做完第 2 步就停了**，第 3 步（改 `rules.md` 阶段读取表）从未做 → 全库零引用。删除理由：①是正式规则的摘录、非新内容；②**摘录已过期**（本次批 2 改口径时只同步了它 3 处）；③留着比删掉危险 —— 下次读 skill 的人看到 `references/rules/` 下有三份「撰写清单」很可能以为它生效。**若要重做，须按当时现行规则重新生成、并同轮把第 3 步做完。**

## 三、判档标准（这次归并的方法本身）

归并的核心不是「把 158k 文档搬进 skill」——那样只是把纯文本从一个文件搬到另一个文件，**强制力一点没变**。真正的动作是给每条经验判它能落到哪一档：

| 档 | 形态 | 判据 | 强制力 |
|---|---|---|---|
| **① hard 闸门** | `report.add()` → exit≠0 | 判定**只需字符串匹配、计数、集合运算**，且**零歧义** | 不可绕过 |
| **② suspect 探测** | `add_suspect()` → 路由给 auditor | 能机械**探测**，但是否违规需看语境（有合法豁免） | 探测不可绕过，判定靠 auditor |
| **③ auditor 必审项** | 写进 `agents/*.md` 契约 | 必须**理解语义/物理**才能判，但有明确判据可写成逐项清单 | 输出契约强制，缺段落即重跑 |
| **④ 工作流 step + 必交产物** | 写进 `SKILL.md`，配产物路径 | 动作发生在**写稿之前**或**跨稿件之外**，闸门看到时已是既成事实 | 产物存在性可校验 |
| **⑤ 规则文本** | 写进 `references/rules/*.md` | 以上四档都落不上 | 靠 LLM 自觉 —— 只在①②③④都不可行时用 |
| **⑥ 案例档案** | 写进 `references/cases/` | Why、原始批注、复盘方法论、案间演变 | 不进必读层 |

判档标准一句话：**能不能只靠字符串和计数判定？** 能 → ①；能探测但需人判豁免 → ②；必须理解语义 → ③ 并配输出契约；动作在写稿前 → ④ 并配产物。

**一条经验可以同时落多档**。例：预设对象 ≤5 → ① 脚本数总量 + ③ auditor 语义核未归类项 + ④ 三张表之一 + ⑤ L1-1 规则条 + ⑥ 案例记失控机理。

**为什么这么分**：五案实测显示，规则的强制力**不取决于写得多清楚、标了几级**（1 级、加粗、★★、「必须」都是给 LLM 看的修辞），取决于**有没有一个不依赖 LLM 意志的执行者**。已有 hard 闸门的那些项（权要总数=10、权 1 ≤400 字、禁写数值、引用句逐字命中），五案一次没出过事；而三条「规则写清楚 + 零闸门」的项（逐槽点数、注入后通读、批注抽象成规则）在同一批案子里各自以「我扫过了」的形式静默失效。

## 五、维护过程中发现的 skill 自身机制（下次改 skill 前必读）

### 5.1 有两层规则文本守卫，不只一层

| 守卫 | 管什么 | 触发形态 |
|---|---|---|
| `verify_rule_anchors.py` | 四份 auditor 契约里 `sed -n` 的**节标题锚点** | 改节标题 → sed 取空 → auditor 拿到空规则包却照样输出「全部 PASS」＝**静默失效** |

| `verify_scoring_excerpts.py` | `scoring.md` 与四份按路摘录的**规则编号分派一致** | 新增规则编号忘了登记摘录 → 红灯 |

2. 批 4 改 G1 白名单时，把「撰写者目录白名单：\`夏晓贝/\`（经验档案 xxb）、\`王培元/\`（经验档案 wpy）」这个连续串重组 → 断言断裂。

**两次都是重组句子而非删规则**，改回保留原串即可。**结论**：改规则正文时，被 31 条断言覆盖的句子要**逐字保留**，重组前先 grep 一遍测试文件。

### 5.2 闸门的四种强度不是文档说的两层

`SKILL.md` 写「阶段 A 机械 + 阶段 B 语义」，读代码后实际是四档（见第三节表）。关键区别：`add_suspect()` 的 docstring 明写**「不计 FAIL、不影响 exit code」** —— suspect 只是「点出来」，判不判违规由 auditor 说。**suspect 档的强制力 = auditor 的可靠性**，是个软接缝。

### 5.3 `check_hard_rules.py` 现有规模

54 处 `report.add()`（hard）+ 17 处 `add_suspect()`（线索）+ 14 个 `suspect_id`。规律清楚：**凡能被正则或计数确定判定的才做成了 hard**，判据全部脱离语义 —— 这正是它可靠的原因，也是它覆盖面窄的原因。

### 5.4 权要侧与说明书侧的正则策略必须不同源

规则 43（权要侧）用**贪婪**前缀 + 禁含「所述/的」；`check_preset_params.py`（说明书侧）必须用**惰性**且前缀 ≥2 字。原因：权要句式规整、`预设××` 后通常紧跟动词，贪婪安全；说明书句子长、`与`／`取`／`、` 连接词多，贪婪会跨语法成分切出假名（实测切出 `预设工作距离与预设单幅采集分辨率`，**反把两个真缺口一起丢了**）。**两侧勿互相搬**，已写进两处注释。
