# H2605066 配电设备火灾识别及主动灭火控制全文稿经验总结

## 来源

- 原稿：本所案卷 `H2605066-全文5稿-…docx`（本机绝对路径不在此记录）
- 用途：本文件只沉淀可迁移的专利撰写经验，供后续全文稿、返修稿和规则自检参考。
- 禁止：不得把本案的具体技术对象、参数值、阈值、附图名称、坐标体系、设备名称或实施例事实直接迁移到其他案件。

## 适用场景

本案例适合参考以下类型案件的全文撰写：

- 涉及感知、识别、空间建模、路径规划、运动控制、闭环反馈的技术方案；
- 交底书只给出较粗的技术链条，需要在说明书中补足可实施细节；
- 权利要求中存在“构建模型”“生成路径”“确定参数”“进行补偿”“执行控制”等上位表述，需要在具体实施方式中拆解为可复现步骤；
- 老板或审查视角关注“如何获得该参数”“具体是多少”“该结果怎么计算”“是否公开充分”的案件。

## 本案例的核心经验

### 1. 权利要求采用“主流程上位 + 从权分段展开”结构

本案权利要求 1 没有塞入全部算法细节，而是用较短步骤搭出完整主流程：

1. 获取感知数据并构建空间模型；
2. 判断风险并识别遮挡或关键对象；
3. 基于空间对象生成路径或策略；
4. 将几何结果转化为可执行模型；
5. 解析模型生成控制参数；
6. 对执行机构误差或死区进行补偿后执行动作。

可迁移经验：

- 权要 1 应展示完整技术闭环，但避免把公式、阈值、算法超参数全部写入独权；
- 从属权要按权要 1 的主步骤逐条展开，每条从权负责一个局部链条；
- 从权内部用 2–5 个短步骤段展开，避免单段过长；
- 每个从权开头应完整引用其所展开的权要 1 主步骤，而不是只引用末端结果。

### 2. 说明书把“上位动作”补成可实施机制

本案具体实施方式中，对权要里的上位动作进行了细化，例如：

- “构建模型”被展开为数据采集、矩阵转换、匹配、去噪、逆投影、坐标系统一等步骤；
- “确定中心/坐标/参数”被展开为体素划分、阈值筛选、聚类、质心或收敛点计算；
- “识别遮挡”被展开为射线构建、求交、局部点云提取、拟合误差判断和区域生长；
- “生成路径”被展开为节点定义、距离与方位计算、禁行区域构建、搜索代价函数和平滑处理；
- “构建轨迹模型”被展开为物理运动方程、标定数据、流量系数、拟合目标和终止条件；
- “生成控制信号”被展开为逆解、姿态变换、角度计算、电机参数转换和死区补偿。

可迁移经验：

- 具体实施方式不能只复述权利要求，应回答“怎么做”；
- 对每个创新步骤，至少补足：对象、输入、处理机制、输出、后续用途；
- 对涉及算法的方法，应点名具体方法或方法族，并给出关键参数、确定依据或示例取值；
- 对涉及控制的方法，应写清控制参数如何从模型或目标结果转换得到。

### 3. 阈值和参数必须有“确定依据 + 具体动作”

本案的优秀做法是：阈值、半径、误差、迭代次数、系数等不是只写“预设”或“自适应确定”，而是说明：

- 来源于历史样本、标定数据、实验样本、材料特性、设备精度或工况范围；
- 通过统计、换算、取高分位值、确定上下界、查表、标定或误差传播等动作得到；
- 在判断或拟合之前已经确定，避免由当前待判断结果反向确定阈值；
- 必要时给出工程示例取值或合理区间，并解释物理理由或工程权衡。

可迁移经验：

- 说明书中出现“预设阈值”“预设条件”“安全半径”“拟合阈值”“最大迭代次数”“控制精度”等，均应补充确定依据；
- 不能只列“根据 A、B、C 确定”，还要写“对 A、B、C 做什么统计、换算、比较或标定”；
- 多级阈值之间要有逻辑关系，例如后级确认阈值应高于前级风险触发阈值，且要解释用途差异；
- 示例值只能用于增强可实施性，不能把本案具体数值机械迁移到其他案件。

### 4. 公式和算法要下沉到说明书，并解释变量

本案的修改经验体现出：

- 权利要求中不写公式；
- 说明书中对关键计算补充公式或计算方式；
- 公式应使用可编辑的字母符号，不用中文作为变量；
- 每个变量需要解释物理意义、单位或来源；
- 公式要说明如何参与后续拟合、判断、控制或输出。

可迁移经验：

- 如果老板批注“怎么计算”“建议补公式”，优先在说明书具体实施方式中补充公式；
- 对质心、变化率、代价函数、运动学关系、控制量换算等内容，不能只写概念，要补可复现计算方式；
- 公式不是为了堆复杂度，而是用于解决公开不充分的问题；
- 补公式后必须继续写其输出结果用于哪个后续步骤。

### 5. 具体实施方式的写法是“权要复述 → 子步骤展开 → 需要说明的是”

本案例中，具体实施方式采用了较稳定的层级写法：

```markdown
在步骤Sxx中，〔复述权要1对应主步骤〕。

其中，〔列出该步骤对应的从权子步骤〕。

需要说明的是，〔解释概念、数据来源、处理机制、参数依据、输出用途或技术效果〕。

具体地，〔给出可实施算法、标定方式、示例值或工程取值范围〕。

值得说明的是，〔说明为什么这样设置能够解决技术问题或避免误判/误控〕。
```

可迁移经验：

- “需要说明的是”后面必须有实质技术内容，不能只套句式；
- 每个创新步骤应至少有一段解释输入数据从哪里来、怎么处理、输出什么、为什么有用；
- 对常规步骤可以简写，对创新步骤和审查风险点必须细写；
- 子步骤与附图节点、权要步骤要保持一致。（注：本案沿用的“子步骤编号 SXX1/SXX2”写法已废止；现行范式为子步骤一律无编号、在“……，包括：”后逐字分号列举，唯一出处 `implementation.md` L8-0/L8-1。）

### 6. 技术效果要绑定技术原因

本案的有益效果不是只说“提高准确性”或“提升效率”，而是将技术效果和具体技术特征对应起来，例如：

- 感知数据与空间模型融合 → 解决二维识别难以表达空间关系的问题；
- 识别空间遮挡对象 → 为路径规划和轨迹构建提供约束；
- 几何路径转化为物理轨迹 → 提高执行结果与实际运动过程的匹配程度；
- 死区补偿和二级判断 → 降低误动作并提升控制响应可靠性。

可迁移经验：

- 有益效果应写成“技术特征 → 技术原因 → 效果”；
- 不要孤立写“提高准确性、稳定性、效率”；
- 每个创新处至少对应一个技术原因；
- 背景技术中的缺陷、权要 1 的主流程、发明内容中的有益效果应互相对应。

### 7. 返修经验：批注往往指向公开充分问题

本案例中，批注集中在：

- 收敛点三维坐标如何计算；
- 热辐射强度变化率如何计算；
- 专业术语是否规范、是否存在歧义。

可迁移经验：

- 当批注询问“如何计算/如何获得/具体是多少/是否清楚”时，通常不是简单加一句解释，而是要补完整计算链或参数确定链；
- 对“变化率、质心、距离、误差、轨迹、控制参数”等结果性概念，应优先检查是否已有公式或算法；
- 对术语类批注，应优先核查本领域惯用表达，避免为了改字而破坏专业术语。

## 可迁移写作模板

### 创新步骤展开模板

```markdown
在步骤Sxx中，〔复述权利要求1中的主步骤〕。

其中，〔该主步骤包括的子步骤或处理对象〕。

需要说明的是，〔定义关键概念，说明输入对象来源和技术含义〕。

具体地，控制器/处理器/系统对〔输入数据〕进行〔统计/匹配/拟合/聚类/搜索/换算/标定〕，得到〔中间结果〕，并将所述〔中间结果〕用于〔后续判断/建模/控制/输出〕。

在一种实施方式中，〔给出示例取值或范围〕。该取值/范围根据〔数据来源〕通过〔具体动作〕确定，使其能够〔解释技术原因和效果〕。
```

### 阈值确定模板

```markdown
所述〔阈值名称〕用于〔筛选/判断/拟合/控制用途〕，其在〔对应判断或处理步骤〕之前确定。

具体地，控制器对〔历史样本/标定数据/实验样本/设备参数〕进行〔统计/换算/取分位值/确定上下界/查表/标定〕，得到〔候选依据〕；再结合〔误差范围/材料特性/控制精度/工况约束〕确定所述〔阈值名称〕。

在一种实施方式中，所述〔阈值名称〕可取为〔示例值或范围〕，实际取值可根据〔本案工况或设备参数〕重新标定。
```

### 算法可实施性模板

```markdown
本实施例采用〔具体算法或方法族〕对〔输入对象〕进行处理。

所述算法以〔距离/误差/相似度/代价函数〕作为度量，关键参数包括〔参数1〕、〔参数2〕和〔终止条件〕。

其中，〔参数1〕根据〔依据〕确定，〔参数2〕根据〔依据〕确定；当〔误差小于阈值/参数变化量小于阈值/迭代次数达到上限〕时停止迭代，输出〔结果〕。

所述〔结果〕用于后续〔判断/路径生成/模型构建/控制信号生成〕。
```

## 后续使用提醒

- 本案例适合学习“说明书如何补足可实施细节”，不适合照搬技术事实；
- 后续遇到“感知→建模→判断→规划→控制”类专利，可参考其展开粒度；
- 后续遇到老板批注“补充公式/具体值/如何获得参数”，应参考本案例的返修方式：补计算方式、补变量解释、补确定依据、补后续用途；
- 若把本案例经验补入 `rules.md`，只补宏观规则，不补本案技术对象和具体参数。
