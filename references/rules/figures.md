# 附图设计规则

本文件用于全文稿、附图说明、说明书附图设计、摘要附图确认和用户手画 Visio 的附图规划任务。

- **L9** = 手画 Visio 流程图/系统图的设计指引（节点文字、编号、连线规范）。
- **L10** = 给生图模型（即梦/Midjourney/SD 等）的「结构示意图提示词」生成规则，画承载创新点的实物/场景图；用户要 AI 出图提示词时读此节。

## L9. 说明书附图设计规则

### L9-1 1级规则

- 不要使用交底书中提供的图作为最终申请图，因为这些图可能与已撰写内容不对应。
- 申请图应根据最终权要和说明书重画。
- 本 skill 只提供附图设计指引，最终的图由用户手工绘制并插入。
- 对每次全文撰写（`全文1稿/2稿/3稿`），在 `全文稿.md` 末尾追加 `## 附图设计（供手画 Visio 用）` 一节；该节只保留在 Markdown，不写入对外交付 DOCX。
- 默认附图集合：图 1 方法主流程图（存在方法独立权要时必备，节点=权 1 分句逐字）＋（按下述条件需要时）系统结构图。**子步骤展开流程图默认不画**——本所审核标准为“一般画 1 个总的流程图即可，其他子步骤不需要”；仅当用户或审核人明确要求为某步骤单独配图时才画，此时按本节子流程图节点规则执行。系统结构图按权要类型细分：存在功能模块式系统/装置独权或系统侧独立结构创新时必备；无对应独权时不得机械生成该类图，应按主要保护主题选择代表性附图。若采用计算机设备式系统/装置权且无模块级创新，不机械生成业务模块式系统图；如需系统图，应画计算机设备结构示意图，节点限于权要已有保护主题，如处理器、存储器、计算机程序、存储介质等，或说明方法流程图已能代表技术方案，系统权仅为兜底保护，不单独绘制模块式系统图。
- 说明书正文不使用“如图N所示，步骤Sxx作为本发明的第N创新块，包括步骤Sxx1至SxxN：”句式引出子流程；主步骤展开范式唯一出处是 `full-draft.md` L8-1。
- 摘要附图的选择规则唯一出处是 `references/rules/full-draft.md` L5：存在方法独立权要时为图 1，无方法独权时按主要保护主题选择代表性附图并与本节附图设计一致。
- 图 1 节点数 = 权要 1 中独立步骤句数量，按 `；` 分号切分。
- 图 1 每个节点文字 = 权要 1 对应分句，逐字照抄技术文字，不改写、不压缩；默认在附图设计表中不保留句末标点，来源比对时以去除句末分号/句号后的权要分句为准，同一稿内统一处理。
- 子流程图节点数 = 被展开父步骤内部的 `SXX1、SXX2、...` 子步骤数。
- 功能模块式系统/装置独权的系统结构图节点数 = 系统独权中模块个数；节点文字 = 系统权要中的模块名，逐字照抄。计算机设备式系统/装置权按前述分支处理。
- 附图设计不得发明权要/说明书里没有的内容。

### L9-2 2级规则

- 用本地 Visio 或 WPS 流程图工具完成最终绘制。
- 不要使用在线流程图截图作为最终申请图。
- 仅当用户或审核人明确要求配子流程图时才判断画法；不得以“从权被分解为多个枚举子步骤”为由默认单独成图（子流程图默认不画，见 L9-1）。
- 主流程图节点编号 = `S11、S12、...、S1N`，与具体实施方式编号一致。
- 子流程图节点文字 ≤10 字，形式为“动作动词 + 产物名”。从对应子步骤句末结果性表达中提取产物名，再前缀加提取、标记、生成、确认、计算、筛选等操作动词；不得照抄整句，不得引入说明书没有的节点内容。
- 子流程图节点编号继承父步骤编号（父 `S12` → 子 `S121、S122、...`）。
- 箭头单线、单向、自上而下。
- 推荐纵向布局，与方法流程图视觉一致。
- 矩形等宽对齐，编号 SXX 用花括号引出线标注在矩形右侧外部，不写在矩形内。
- 不在 Visio 中嵌入特殊字体；用宋体或微软雅黑等系统字体，避免导出乱码。

### L9-3 附图设计输出模板

在 `全文稿.md` 末尾追加：

```markdown
## 附图设计（供手画 Visio 用）

> 用途：以下内容供作者在本地 Visio 中手画附图。每个矩形里的文字必须与本节一致，编号 S11/S121 等标注在矩形右侧花括号引出线外。最终 Visio 文件不替换本节，本节由用户在交稿前自行删除或保留。

### 图 1 — <方法名称> 流程示意图（存在方法独权时同时作为摘要附图，见 full-draft.md L5）

- 来源：权利要求 1 / 具体实施方式 S11–S1N
- 编号方向：自上而下 S11 → S12 → … → S1N
- 节点文字（照抄权要 1 分句）：

  | 编号 | 节点文字（矩形内）|
  |---|---|
  | S11 | <权要1分句1原文> |
  | S12 | <权要1分句2原文> |
  | … | … |
  | S1N | <权要1分句N原文> |

- 连线：S11 → S12 → … → S1N，单线、单向、纵向
- 摘要附图：与本图完全相同

### 图 2 — <子流程名称> 示意图【仅当用户/审核人明确要求为该步骤配子流程图时才生成本块，默认删除（L9-1 子流程图默认不画）】

- 父步骤：S1X（如 S12）
- 来源：权利要求 X / 具体实施方式 SXX1–SXXN
- 编号方向：自上而下 SXX1 → SXX2 → … → SXXN
- 节点文字（≤10字「动作+产物名」短语）：

  | 编号 | 节点文字（矩形内）| 对应说明书内容 |
  |---|---|---|
  | SXX1 | <≤10字短语> | <一句话或行号锚点> |
  | … | … | … |
  | SXXN | <≤10字短语> | <一句话或行号锚点> |

- 连线：SXX1 → SXX2 → … → SXXN，单线、单向、纵向

（仅当用户/审核人对不止一个主步骤明确要求配图时，重复“### 图 N — …”块；默认不生成。）

### 图 N — <系统名称> 结构示意图

- 来源：权利要求 N（系统独权）
- 节点文字（照抄模块名）：

  | 序号 | 模块名（矩形内）|
  |---|---|
  | 1 | <模块1名称> |
  | … | … |
  | M | <模块M名称> |

- 连线：按系统权要中模块顺序自上而下单向连接（也可改横向，但同稿内统一）

### 手画 Visio 提示

- 矩形等宽对齐，纵向布局推荐每矩形高 ≈ 节点文字 2–3 行。
- 编号 SXX 用花括号引出线 `}` 标注在每个矩形右侧外部，不写在矩形内。
- 箭头单线、向下、居中。
- 节点文字必须与本节表格完全一致；如发现表达不顺，回头修说明书与本节，不要单独改 Visio。
- 不在 Visio 中嵌入特殊字体；用宋体或微软雅黑等系统字体，避免后续导出乱码。
- 老板批注要求"修改附图""调整文本框宽度一致""图内排版"等附图本体修改时，**默认不由 AI 在 DOCX XML 内处理**：本所附图通常以 OLE 嵌入对象（Visio.Drawing 或同类）方式存在于 `word/document.xml`，文本框宽度、连线、排版等属性写在被嵌入的 `.vsd*` 内部，AI 编辑 `document.xml` 无法触达。**Why:** 审核v2 全文3稿返修中王工对图1/图2/图3 三处批注均为"修改附图，调整文本框宽度一致"，但锚定段全部是 OLE `<w:object>...<o:OLEObject>` 节点，强行在 XML 层改宽高仅能改 `<v:shape style="height...width...">` 容器尺寸，无法对齐图内文本框。**How to apply:** 此类附图本体批注由用户在本地 Visio/WPS 重画后整图替换；AI 在完工报告中将该批注列为"待用户在 Visio 中手工处理"，不强行 fake 一个修订；其余文本批注照常注入 `<w:ins>/<w:del>` 留痕。
```

### L9-4 自检清单

- 图 1 节点数是否等于权要 1 中以“；”分隔的步骤数。
- 图 1 节点文字是否逐字等于权要 1 各分句去除句末标点后的技术文字，分号/句号处理是否同稿统一。
- 每张子流程图的子节点数是否等于具体实施方式中 `SXX1..SXXN` 的数量。
- 子流程图节点文字是否 ≤10 个中文字，且与对应子步骤的产物一致。
- 系统图模块数和模块名是否与系统独权一致。
- 摘要附图声明是否与按 `full-draft.md` L5 选定的附图完全相同（存在方法独权时即图 1）。
- 附图清单是否与 L7 附图说明一致。

## L10. 结构示意图「生图模型提示词」生成规则

> 触发：用户要求“生成结构示意图/系统图/实物图的**生图提示词/AI 出图提示词**”，准备把提示词投喂即梦/Midjourney/SD/DALL-E 等生图模型。**区别于 L9**：L9 是手画 Visio 流程图/模块图的设计指引；L10 是给生图模型的自然语言提示词，画的通常是**承载创新点的实物/场景结构示意图**。两者可并存——同一案件既可有 L9 的 Visio 流程图，也可有 L10 的实物结构示意图。

### L10-0 核心纪律：提示词必须从说明书反推，禁止脑补

- **唯一信源是本案说明书/权要**，不是 AI 对“这类系统长什么样”的常识想象。生成提示词前，**必须先在 `全文稿.md`/交底书中检索并锁定**：实施例载体（如“金属冶炼加热炉”）、传感器类型与布设（如“沿炉膛上中下布设 24 个同型号温度传感器”）、工艺阶段名（如预热/升温/保温/出炉准备）、监测维度（如炉膛空间温差/温度上升速率）、各创新点表述。提示词里每个具象元素都要能在说明书里指到出处。
- **创新点是图的灵魂**：实物结构图不能画成“看不出发明的普通设备图”。先列出本案 N 个创新点（通常对应各从权/创新块），再为**每个创新点指定一种画面可视化呈现**，确保审查员一眼能从图里看到发明在哪。漏掉创新点的实物图等于弱化创造性，不合格。
- **术语忠实**：说明书用“工业控制系统”就不要在图注/正文里造“网关/服务器机柜/大屏”等新名词；这类词只能作为**画面具象化的临时替代**，且须向用户说明“非原文术语，仅供出图，勿写入说明书”。
- **不发明说明书没有的结构**（与 L9-1 一致）。拿不准某元素是否属于本案时，先回说明书核对或问用户，不要静默编入。

### L10-1 标准工作流（每次生成前按序执行）

1. **定位图的角色**：先问/确认这张图要画成哪一类——(a) 实物/场景结构示意图（创新点嵌入实物载体，**最常见**）；(b) 功能模块架构图（抽象方框体现创新链条）；(c) 计算机设备结构图（处理器/存储器/程序，仅兜底系统权用）。三类对应不同提示词骨架。
2. **检索创新点与实施例元素**：在 `全文稿.md` 检索载体、传感器、阶段、监测维度、创新块；用对照表确认“拟写入提示词的元素 ↔ 说明书出处”。
3. **创新点→可视化映射**：列一张「创新点 | 在图中怎么体现」表，逐条落实。
4. **产出提示词**：英文版（投喂模型用，推荐）+ 中文对照版 + 画面布局示意（ASCII 草图）+ 可选强化/负向词。
5. **诚实声明（必附）**：说明生图模型对中文标号、精密多框、固定数量元素（如“24 个传感器”）渲染不可靠，提示词宜作概念草图，最终专利附图建议改用 Visio/SVG 精确版；并提示哪些元素是原文、哪些是出图用的具象替代。

### L10-2 黑白专利风提示词骨架（可复用模板）

英文主提示词固定包含以下要素层，按本案内容替换 `<...>`：

```
A black and white technical illustration in patent drawing style, clean engineering ink line-art,
pure white background, black outlines only, no color, no shading except thin diagonal hatching for
cut/cross-section surfaces, flat 2D <side|top> view, no perspective, no people.

<载体场景：如 an industrial heating furnace in cutaway cross-section, furnace wall edges hatched>
<创新点1 的可视化：如 multiple temperature sensors at distinct upper/middle/lower positions inside
the chamber, interconnected by dashed lines forming a spatial-collaboration network (not isolated points)>
<创新点2 的可视化：如 a monitoring screen showing a process curve split into labeled segments
(preheating / heating-up / holding), each segment bounded by its own upper-lower limit band — stage-wise dynamic boundary>
<创新点3 的可视化：如 a graded three-level warning indicator (low/medium/high) plus a numeric anomaly score>
<数据/链路：如 sensor wires bundle into a cable → data-acquisition unit → control system, left-to-right with single arrows>

All parts as simplified mechanical line-art, thin uniform strokes, connected by straight wires/arrows,
each component tagged with a reference numeral and leader line, minimalist monochrome patent figure,
high contrast, schematic, no photographic texture, no gradient.
```

要点：①黑白／纯白底／仅黑线／剖面用斜线 hatching；②无透视无人物无照片质感；③各部件带标号引出线（reference numeral + leader line）；④创新点逐条以独立短句嵌入；⑤连线用 single arrows 表数据流向。负向提示词常用：`--no color, photograph, realistic texture, 3D render, gradient, blurry, people`。

### L10-3 风格档位

- **黑白工程线描图（专利风）**：默认。最贴合专利附图惯例，`ink line-art / line drawing / USPTO patent drawing style / reference numerals / hatching`。
- **黑白立体渲染图**：仅当用户明确要产品效果感时用，加 `monochrome 3D render, soft shadows`；一般不推荐作正式附图。

### L10-4 自检清单（出提示词前逐项过）

- 载体场景、传感器类型/数量/布设、阶段名、监测维度，是否都能在说明书指到出处？无出处的具象元素是否已剔除或标注为“出图用替代”？
- 本案每个创新点是否都在提示词里有对应的可视化呈现？有没有漏掉某个创新块？
- 是否避免把图画成“看不出发明的普通设备图”？
- 是否用了原文术语（如“工业控制系统”），未擅自造新模块名并写入说明书？
- 是否同时给了英文版＋中文对照＋布局草图＋黑白风格词？
- 是否附了“生图模型局限 + 建议精确版改用 Visio/SVG”的诚实声明？
