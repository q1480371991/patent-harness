# scoring 摘录 — content-auditor 专用

> 本文件是 `scoring.md` 的静态摘录（按路摘录的实体化文件），仅供主 agent 以**路径**传给 `content-auditor`。**修改 `scoring.md` 评分项或前置纪律时，必须同步更新本文件**。计分方法与多路合并口径不在本摘录内——那是主 agent 的职责。

## 评分前置纪律（防 AI 自评虚高）

必须先逐条列出"规则编号 → PASS/FAIL → 证据（原文片段或位置）"，分数由证据汇总得出，不得跳过证据直接给分。无证据的 PASS 一律视为未检查。

## 本路 1 级硬规则（零容忍，任一 FAIL → 整体不通过）

- L6-1 发明内容与权要一一对应（漏覆盖任一条权要同时构成**完整性级**缺陷，报告中显式标注）、有益效果给技术原因、发明内容/有益效果无权要外实体名词或判断/步骤（反向断言三节，差集非空同为**完整性级**；唯一出处 `full-draft.md` L8-0）
- **L6-1 有益效果首项对应背景核心问题（W07）**：直接解决背景技术收口那一个核心技术问题的效果必须排在第（1）项；把次要/通用/实现细节效果置于首项即 FAIL。分项编号格式由 `check_hard_rules.py` 规则 22 终判，本路沿用，只判排序的语义正确性
- **L6-1 第二方面系统复述段固定套话（W05）**：由 `check_hard_rules.py` 规则 30 确定性终判（计算机设备式骨架、不写"的步骤"），本路只沿用不重判；另须逐条处置 `suspect_manifest.content` 中 `S-W05-aspect-name` 的方法名简称线索（确认违规并给出应写全称，或给证据豁免）

- L6-2 各条

## 判定与报告要求

- 1 级：逐条 PASS/FAIL，FAIL 必须给【规则编号 + 原文位置 + 问题】。
- 2 级：逐条判定，不适用的条目注明理由（由主 agent 从分母剔除）。
- 报告结构按本路契约 Output Contract 执行；每个 PASS 必附原文引用片段。
