# md 审查评分卡（写入 DOCX 前的质量闸门）

本文件规定**权要稿 / 全文稿在 md 阶段写入 DOCX 前的量化把关方法**。目的：把分散的逐条自检变成"完整性一票否决 + 质量百分制"的可追溯闸门，并定位失分项。

**唯一出处原则**：本文件只规定**评分机制**（怎么判、怎么扣、怎么过），不复述具体规则内容；每个评分项均**引用现有规则编号**（G1–G7、L1–L9 及其 1 级/2 级条目、`claims-format-standard.md`），违反哪条就扣哪条、报哪条编号。

适用时机：`权要稿.md` 完成时（权要一稿 / 权要返修），`全文稿.md` 完成时（全文一稿 / 全文返修）；写入 DOCX 前必过此闸。

---

## 一、两段式闸门总则

```
第一闸 完整性（一票否决）：缺块/漏项 → 直接 FAIL，不进入评分，列出缺什么并回修
第二闸 符合度评分（仅在完整时执行）：
  - 逐条规则判 PASS / FAIL，每条 FAIL 必须给【规则编号 + 原文位置 + 问题】
  - 1 级硬规则：任一 FAIL → 整体不通过（无论总分多高）
  - 2 级质量规则：按权重算百分比
通过标准 = 完整性 PASS 且 1 级硬规则 100% 通过 且 2 级质量分 ≥ 90%
```

**评分前置纪律（防 AI 自评虚高）**：必须先逐条列出"规则编号 → PASS/FAIL → 证据（原文片段或位置）"，分数由证据汇总得出，不得跳过证据直接给分。无证据的 PASS 一律视为未检查。

---

## 二、第一闸：完整性一票否决清单

任一项缺失即 FAIL，报告缺失项后回修，不进入评分。

### 权要稿完整性
- 权利要求书（L1）、技术领域（L2）、背景技术（L3）三块齐全。
- 权要集结构完整：方法独权 + 方法从权 + 系统/装置独权（+ 存储介质权），编号连续无断号（L1-1）。
- 每条从属权要都有所依附的独权/从权，无悬空依附（L1-1）。

### 全文稿完整性
- 说明书摘要（L4）、摘要附图（L5）、发明内容（L6）、附图说明（L7）、具体实施方式（L8）齐全；附图设计节（L9）只做**存在性检查**（附图内容与图文一致性深审不在 md 审查闸门范围，由用户人工把关）。
- **发明内容对每条权要均有对应展开**（L6-1）；缺任一条权要的对应 = 完整性 FAIL。
- **具体实施方式对权要每一条步骤均有解释**（L8-1）；漏任一主步骤 Sxx 或其从权子步骤 = 完整性 FAIL。
- **权要内撞名校验**（`claims.md` L1-1）：同一实体名词在权利要求书内指两个不同对象 = 完整性 FAIL；权要稿阶段拦截，全文阶段发现按 `full-draft.md` L8-0 撞名复校退回。
- **Sxx 框架同构校验**（L8-0）：步骤**数量**由 `check_cross_block.py` X1 终判，框架句**文字层**由 impl-auditor 以 `claims_md_path` 为基准逐字比对后回传（该 md 基准与最新已审权要 DOCX 的一致性由主 agent 在全文一稿 step 1 回写保证，并经 `timestamp_guard.py`/`fingerprint_claims.py --check` 守卫）；global-auditor 只汇总二者结论，不自行从 DOCX 提取。数量不等或文字不同 = FAIL。
- **反向特征校验（同构三节）**（L8-0）：提取具体实施方式、发明内容、有益效果三节框架句/对应句的实体名词与判断条件集合，与权利要求书特征集合做差集；差集非空 = FAIL，逐项列出多出的特征（功能性换述与白名单豁免项不计入）。
- **步骤集差集校验**（L8-1）：权 1 分句与各从权分句的步骤短语集 vs 三节步骤短语集做差集；缺任一权要步骤 = FAIL，多出步骤逐项列出。具体实施方式 Sxx 顺序须与权 1 分句顺序一致（顺序局部同构）。
- 权利要求书未被擅自改动（全文阶段权要冻结，`full-draft.md` 权要冻结条）：以主 agent 传入的 `fingerprint_claims.py --check` 结果（`fingerprint_check_result`）PASS 为判据，global-auditor 汇总；结果缺失时报告“冻结校验缺失”，不得凭 md 目测放行。

> 第一闸专抓"内容缺斤少两"。分数高但缺块，仍判 FAIL。

> **机械执行层（双通道，脚本优先）**：Sxx 步骤数同构由 `scripts/check_cross_block.py` 终判；反向特征差集、权要内撞名、步骤集差集由 `scripts/verify_claims_alignment.py` 终判——其 `hard` 项（步骤集差集缺失）与 auditor 冲突时以脚本为准，`suspect` 项（反向特征/撞名的正则近似线索）以 `alignment_check_result` 字段回传各路 auditor 逐条复核处置。权要基准时效由 `scripts/timestamp_guard.py` + `scripts/fingerprint_claims.py --check` 前置守卫，二者任一 exit=3 时全文稿未过闸、不进入本评分。

## 三、第二闸：符合度评分

### 评分项与权重（引用规则编号，不复述内容）

**多路归属**：本闸门由多路审查（multi-auditor）并行执行，每个评分项由行末【】标注的审查路判定——【global】= `global-auditor`、【claims】= `claims-auditor`、【content】= `content-auditor`、【impl】= `impl-auditor`。完整性一票否决由 `global-auditor` 判定（其中 L6 权要覆盖、L8 反向特征/漏解释两类完整性级缺陷由 content / impl 专审发现后回传）。各路契约见 `agents/*-auditor.md`。

**auditor 摘录范围（唯一出处）**：本文件**不整篇传入任何 auditor**。按路摘录已**实体化为静态文件** `references/rules/scoring-{claims,content,impl,global}.md`，主 agent 只把对应文件的**路径**（`scoring_excerpt_path`）传给各路 auditor，由其自行 Read；每份摘录含：评分前置纪律 + 本路评分项 + 判定要求，`scoring-global.md` 额外含第一闸完整性清单。"计分方法"与多路合并口径只归主 agent 使用，不进入任何摘录文件。**维护纪律**：修改本文件的评分项、完整性清单或前置纪律时，必须同步更新对应摘录文件。

**A. 1 级硬规则（零容忍，任一 FAIL → 整体不通过）**

权要稿：
- G3 链条闭合、G4 术语与"所述"、G5 禁用措辞、G6 公式/模型/阈值（`global.md`）【global】
- L1-1 全部：权要数量与结构、权 1 ≤400 字、权 1 解决技术问题、分号断行、一个句号、从权完整引用权 1 主步骤、从权依附多元化（非全部依附权 1）、"所述"与"一种"用法、数据来源与用途、一条从权只解决一个问题、权要内无撞名（同名实体不指两义）【claims】
- L2-1 技术领域、L3-1 背景技术 全部【global】
- 断行/分号/从权粒度依附符合 `claims-format-standard.md`【claims】

全文稿：
- G3、G4、G5（`global.md`）；G6 全局语义合规【global】——其中 G6-1 公式五项/统计术语五项/判断分支三项清单与模型四维度测度的**逐项清单判定归【impl】**（见下方 L8-1 行），本行不重复判
- L6-1 发明内容与权要一一对应、有益效果给技术原因；发明内容/有益效果无权要外实体名词（反向断言三节，唯一出处 `full-draft.md` L8-0）【content】
- L8-1 全部：解释每条权要步骤、阈值给确定依据、算法表述操作可实施优先（点名处有操作展开与超参，概括处操作写清）、求解/变换类四段清单与悬空指称测试、判断步骤用规定句式、公式规范、Sxx 展开范式、步骤集差集（三节无缺失/多余步骤）、顺序局部同构（具体实施方式 Sxx 序=权 1 分句序）、公式/统计/判断三类最小必填清单与模型四维度测度（唯一出处 `global.md` G6-1）、可实施（专利法 26.3）【impl】
- L4-1 摘要（≤300 字、术语一致）、L5-1 摘要附图、L7-1 附图说明自身格式（编号连续、每图一句功能描述；与 L9 附图设计的一致性深审不在闸门范围）【global】

**B. 2 级质量规则（加权扣分，算百分比）**

- 权要稿：L1-2【claims】、L2-2、L3-2【global】各条
- 全文稿：L4-2【global】、L6-2【content】、L8-2【impl】、L7-2【global】各条

### 计分方法

- **1 级硬规则**：逐条 PASS/FAIL。只要有 1 条 FAIL，闸门结论=不通过，并列出违反的规则编号（无论 2 级分多高）。
- **2 级质量分** = 通过的 2 级条目数 ÷ 适用的 2 级条目总数 × 100%。不适用的条目（如本案无系统从权）从分母剔除并注明。
- **多路合并口径**：各路只对本路范围评分项打分；任一路任一条 1 级 FAIL → 整体不通过；2 级质量分 = Σ各路通过条目数 ÷ Σ各路适用条目数 × 100%（分子分母跨路合并后再算百分比，不做各路平均）。
- **总结论**：完整性 PASS + 1 级全过 + 2 级 ≥ 90% → **通过，可写入 DOCX**；否则 **不通过，回修**。

## 四、输出格式（评分报告）

```
## md 审查评分报告（权要稿 / 全文稿）

### 第一闸 完整性：PASS / FAIL
（FAIL 时列缺失项）

### 第二闸 符合度
1 级硬规则：N/N 通过（FAIL 项逐条列：规则编号 + 原文位置 + 问题）
2 级质量分：XX%（FAIL 项逐条列：规则编号 + 位置 + 建议）

### 结论：通过 / 不通过
（不通过时给出"改哪几处可达标"的最短回修清单）
```

报告只在 md 阶段内部使用，用于决定是否放行写入 DOCX；不另出独立长篇撰写检查报告（除非用户要求）。

**执行留痕（防自评虚高）**：评分报告必须落盘为 `docs/审查报告-<稿次>.md`（含逐条证据），作为进入 DOCX 注入的前置产物；无落盘报告 = 未过闸。1 级硬规则的每个 PASS 必须附原文引用片段。**多路审查时由主 agent 合并落盘一份**：合并结论在前（按上文合并口径计算），各路原始报告全文附后；同位置同规则的重复项去重，跨路冲突按 `rules.md` 冲突处理原则裁决。

## 五、与现有自检清单的关系

- 本评分卡是 L1-3 / L2-3 / L3-3 / L4-3…L9 各自检清单的**量化封装**，不替代、不复述它们——逐条判定时仍以各 `-3 自检清单`和对应 `-1/-2` 规则为准。
- 跨块一致性（发明内容/具体实施方式对权要的引用一一对应）按 `global.md` 跨阶段总自检执行，计入第一闸完整性与 1 级硬规则。
