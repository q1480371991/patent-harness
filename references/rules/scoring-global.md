# scoring 摘录 — global-auditor 专用

> 本文件是 `scoring.md` 的静态摘录（按路摘录的实体化文件），仅供主 agent 以**路径**传给 `global-auditor`。**修改 `scoring.md` 评分项、完整性清单或前置纪律时，必须同步更新本文件**。计分方法与多路合并口径不在本摘录内——那是主 agent 的职责。

## 评分前置纪律（防 AI 自评虚高）

必须先逐条列出"规则编号 → PASS/FAIL → 证据（原文片段或位置）"，分数由证据汇总得出，不得跳过证据直接给分。无证据的 PASS 一律视为未检查。

## 第一闸：完整性一票否决清单（按 stage 取对应清单）

任一项缺失即 FAIL，报告缺失项后回修，不进入评分。

### 权要稿完整性（claims-draft）
- 权利要求书（L1）、技术领域（L2）、背景技术（L3）三块齐全。
- 权要集结构完整：方法独权 + 方法从权 + 系统/装置独权（+ 存储介质权），编号连续无断号（L1-1）。
- 每条从属权要都有所依附的独权/从权，无悬空依附（L1-1）。
- 权要内无撞名：同一实体名词不在权要内指两个不同对象（L1-1；由 claims-auditor 专审发现后回传）。

### 全文稿完整性（full-draft）
- 说明书摘要（L4）、摘要附图（L5）、发明内容（L6）、附图说明（L7）、具体实施方式（L8）齐全；附图（L9）只检查 `docs/figures/figure-1.png` 存在且由最新权要生成（图文一致性由渲染脚本构造保证）。
- 发明内容对每条权要均有对应展开（L6-1；由 content-auditor 专审发现后回传）。
- 具体实施方式对权要每一条步骤均有解释（L8-1；由 impl-auditor 专审发现后回传）。
- Sxx 框架同构校验（L8-0）：步骤数量由 `check_cross_block.py` X1 终判、框架句文字层由 impl-auditor 逐字比对后回传；本路只汇总二者结论，不自行从 DOCX 提取（md 基准与最新已审权要 DOCX 的一致由主 agent 回写保证并经守卫脚本校验）。
- 反向特征校验（同构三节：具体实施方式+发明内容+有益效果）（L8-0；由 content/impl-auditor 专审发现后回传）。
- 步骤集差集校验 + 顺序局部同构（L8-1；由 impl-auditor 专审发现后回传）。
- 权要基准无撞名（L1-1 / L8-0 撞名复校；撞名则退回权要侧改名）。
- 权利要求书未被擅自改动：**分离式工作流为「全文阶段权要冻结」、直写全文稿为「会话内基准自锁」**（适用边界唯一出处 `implementation.md`「阶段映射与权要冻结」节），两者判据同为主 agent 传入的 `fingerprint_check_result`（`fingerprint_claims.py --check` 结果）PASS；结果缺失时报告“冻结/自锁校验缺失”，不得凭 md 目测放行。返修阶段入口不跑 `--check`，本项据实标 ➖。
